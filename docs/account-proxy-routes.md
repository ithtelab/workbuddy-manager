# 出口线路（代理池）

管理员可以给每个账号指定一条出口线路，也可以在添加账号时选择线路。
登录授权、轮询、签到、积分、模型查询、连通性测试、地区注册、试用领取和令牌续期
均使用该账号的出口。线路被移除、被停用或地址无效时，相关请求**明确失败**，
不会悄悄回退到别的出口 —— 出口在风控眼里是特征，被换掉比报错更糟。

## 配置

**在面板里配**：「设置 → 代理」页面（仅管理员可见）。它分成三块：

| 区域 | 作用 |
|---|---|
| **代理线路**（池） | 新增 / 编辑 / 删除 / 批量导入线路，逐条**测试**（显示耗时、出口 IP 与归属地）；每条线路有权重与启用开关 |
| **全局出口代理** | 兜底出口，存在面板设置里，覆盖环境变量 `WB_HTTP_PROXY` |
| **更新下载代理** | 一键更新下载发布包时用，只认 `http://` 与 `https://` |

### 池：策略、权重、启用

页面顶部一行是池配置：**开关** + **策略** + **间隔**。

- **策略**：`优先级`（权重最大的先用）、`轮询`（依次轮）、`随机`（按权重加权随机）、
  `最少调用`（最近一分钟调用最少的那条，近似「最少连接」）。
- **权重**：写在线路旁边的数字，缺省 100；越大越常被选中。只有一条线路时不必管它。
- **启用**：停用的线路不参与池挑选；**绑着它的账号请求会失败**并说明是这条线路停了，
  而不是被换到别处。
- **间隔**：同一个账号多久重新挑一条出口，默认 300 秒。窗口内固定走同一条 ——
  一会儿换一个出口在风控眼里就是特征。

### 账号绑定：一个账号最多一条线路

在「绑定账号」里逐行选：选某条线路 = 绑上去；选「默认（跟随池策略）」= 解除绑定，
交给池按策略分配；选「直连（不走代理）」= 这个号**显式绕过池与全局出口代理**。
**没有绑定**的账号才走池；池也关着时走全局出口代理，再没有就直连。

> 直连使用上游 `__direct__` 保留线路名（2.6.0+）。回退到旧上游时，绑了直连的账号
> 会报「未知线路」，不会静默走代理 —— 这是刻意的 fail-closed。

于是两种常见诉求这样表达：

- **一个号一个独立住宅 IP**：给每个号各绑一条线路。住宅代理把国家 / 城市 / 会话名写在
  用户名里，**一个会话名粘一个出口 IP**，所以每条线路配不同的会话名；
- **几个号共用一条出口**：把它们绑到同一条线路（省 IP 额度，但同一个 IP 上挂多个号，
  上游按 IP 聚类时容易互相关联 —— 绑到 3 台以上列表里会标出来）。

「自动分配 N 台」用来铺开：填个数按一下，先挑没绑线路的账号，再按昵称稳定排序补齐
（导入几条住宅代理、手上有上百个号时不必一台台点）。

### 直接改文件

线路表读取自 `WB_UPSTREAM_CONFIG` 指向的配置文件（通常是上游的 `config.json`），
只动 `proxies` 段，其它键一律不碰：

```json
{
  "proxies": {
    "px-cn": "socks5://用户_c_CN_city_Shanghai_s_abc:密码@网关:10000",
    "px-hk": {"url": "http://proxy.example:8080", "weight": 30, "enabled": true}
  }
}
```

值可以是地址字符串，也可以是带 `weight` / `enabled` 的对象。地址支持 `http://`、
`https://`、`socks5://`、`socks5h://`（socks5 依赖 `socksio`，已随
`server/requirements.txt` 一起安装）。住宅代理服务商常把参数写在用户名里，例如
`用户_c_CN_city_Shanghai_s_<会话名>`（国家、城市、会话名）—— 照抄服务商给的格式即可。

池配置（开关 / 策略 / 间隔）存在面板设置里，不在上游配置文件中。

### 凭据只进不出

代理地址与认证信息只保存在服务端：列表接口一律回**脱敏串**（密码显示为 `***`），
编辑时保留 `***` 就等于不改密码。账号文件里只存**线路名**，浏览器拿到的列表不含密码。

### 旧版的 `{account}` 写法

1.0.84 版本曾让用户把 `{account}` 写在线路地址里（每个账号渲染出自己的会话名）。这个
写法**已被池方案取代**，但**仍然有效**：带占位符的地址按账号渲染，会话名沿用账号文件
里存下的 `proxy_session`（没有就按昵称、再退到账号 ID 前缀）。新界面不再提供它 ——
要「一个号一个 IP」请各自绑一条线路。

### 其它相关项

`WB_DEFAULT_ACCOUNT_PROXY` 可指定新账号的默认线路，空值保持原有出口行为。
显式选择「默认出口」会取消账号绑定。

`WB_HTTP_PROXY` **只作用于公网目标**：内网与本机地址（`127.0.0.1`、私有网段、
`workbuddy2api` / `host.docker.internal` 这类内网名）始终直连 —— 否则配了代理之后，
面板连自己上游的那一跳会被交给代理，直接读不到上游状态。面板设置里的「全局出口代理」
与它有同样的行为，只是可以在界面上开关与修改。

账号线路表是管理端共享的配置。使用多个上游实例时，各实例应配置相同名称和地址的
线路，账号的读取、写入及重载仍作用于当前选中的分组。

## 上游兼容条件

管理端的腾讯请求由本功能处理；聊天请求及上游后台任务由 workbuddy2api 发出，
需要上游同时支持 `proxies` 配置和账号文件顶层的 `proxy` 字段，并在令牌刷新写回时
保留该字段。原版上游不具备这一支持，仅安装管理端不能保证聊天也走绑定线路。

上游**整个进程**的出口代理是另一回事，且开箱可用：给上游容器设 `HTTP_PROXY` /
`HTTPS_PROXY`（以及 `NO_PROXY`）即可，大小写都认 —— 走的是 Go 标准库的代理解析，
作用于上游的全部出站请求（含聊天）。它给不了「每个账号一条线路」，只适合
「整台机器的出网都要过代理」这种部署（issue #136）。

Python 活动任务执行器还需要读取 `WB2A_PROXY_CONFIG` 和账号的 `proxy` 字段，
按账号绑定出口；管理端已将配置文件位置传递给执行器。未适配的执行器不能用于
要求全流程出口一致的账号。

修改线路绑定后，管理端请求当前分组的上游重载。非默认分组没有配置容器名时，
由支持账号热加载的上游读取变更；无法调度重载时，响应的 `reload_triggered` 为 false。
调整线路表本身之后，应重启相关上游实例以重新读取配置。
